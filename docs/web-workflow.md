# Работа в `web/` (интерфейс v2) — правила

Решение Валерия и Никиты (27.11): основа — этот репозиторий, эксперименты с отдельной системой закрыты. Никита — collaborator и владелец `web/`.

> Тот же текст — [`web/CLAUDE.md`](../web/CLAUDE.md), его читает агент, работающий в `web/`. Правки — в обоих файлах.

**Зона**
- Правишь только `web/`.
- `src/`, `data/`, `stand.yml`, `.github/workflows/`, `Makefile`, корневой `CLAUDE.md` — не трогаешь.
- Нужно изменение API — заведи issue с меткой `api-v2`: что нужно, зачем, пример запроса и ответа. Отвечает серверная команда, контракт — [`docs/api-v2-web.md`](api-v2-web.md).

**Ветки и PR**
- Ветка — от свежего `main`. Маленькие PR: одна функция — один PR.
- В `main` не пушишь. Force push и удаление веток нельзя.
- CI должен быть зелёным: `make web-test` и сборка `npm run build` с проверкой типов. Перед push — `make check`.
- Проверка — на **превью-адресе** из комментария бота в PR (`pr-N`): телефонная ширина 390 px, сценарий из описания PR.
- Сливает штурман (Валерий) — при зелёном CI и проверке на превью.

**Общие файлы**
- `STATUS.md` и `DECISIONS.md` в ветках не правишь.
- Решения и статус — в описание PR, раздел «Для общих файлов». Их переносит штурман.

**Правила продукта, которые касаются `web/`**
- **Уровень механика не хранить:** слать `level: "auto"`, ключ `dm-level` в `localStorage` и вопрос при первом входе убрать. Решение Валерия: смены, подмены.
- Цифры и страницы показывать как прислал сервер. Интерфейс их не пересчитывает и не дописывает.
- Неизвестные поля и события пропускать. Новое поле может прийти раньше, чем интерфейс его покажет.
