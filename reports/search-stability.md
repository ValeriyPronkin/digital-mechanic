# Стабильность ответов на открытую половину (26.11.2026)

Задание штурмана: один и тот же вопрос → те же страницы в 3 из 3 прогонов; найти общую причину колебаний Q16
(и Q03, Q15, Q23, Q36). Сводка — `make eval-stability PREFIX=… RUNS=3` (`scripts/eval_stability.py`).

## Что колеблется (разбор по шагам)

| Шаг | Детерминирован? | Как проверено |
|---|---|---|
| Эмбеддинг запроса (Yandex) | да | 5 вызовов на один текст — векторы совпадают, ошибок нет |
| Поиск по одному запросу (BM25 + эмбеддинги + RRF) | да | 4 запроса Q16 × 5 раз — по одной выдаче на запрос |
| План поиска (модель, t = 0,2) | **нет** | 6 прогонов: Q16 — 2 разных плана, Q03 — 4, Q15 — 5, Q23 — 3, Q36 — 4 |
| План поиска при t = 0 | **нет** | те же 6 прогонов: 3, 3, 4, 3, 3 разных плана — DeepSeek недетерминирован и при 0 |
| Ответ модели: какие страницы цитировать | **нет** | одинаковый набор страниц во всех 3 прогонах — у 9 из 20 вопросов |

Q16: стр. 581 (перечень одноразовых уплотнений) или 582 — зависит от формулировки запроса в плане.

## Что пробовали (3 × eval-open на каждый вариант)

| Вариант | Засчитано | Одинаковые страницы 3/3 | Одинаковый итог 3/3 | Колеблются |
|---|---|---|---|---|
| `main` (до) | 16, 16, 17 | 9/20 | 19/20 | Q16 |
| план t = 0 + первым запросом сам вопрос + слияние суммой RRF | 14, 14, 14 | 9/20 | 18/20 | Q16, Q37 |
| план t = 0 + слияние суммой RRF с гарантией лучшей страницы каждого запроса | 15, 17, 16 | 8/20 | 18/20 | Q16, Q23 |
| план t = 0 + ответ t = 0 (`LLM_TEMPERATURE=0`), слияние как в `main` | 16, 15, 16 | 10/20 | 17/20 | Q16, Q23, Q24 |

- Сам вопрос механика первым запросом хуже пересказа моделью: разговорные формулировки («можно ли своим ходом
  перегнать…») уводят поиск — Q24 и Q34 теряли эталонную страницу.
- Сумма RRF стабилизирует выдачу части вопросов, но выкидывает страницу, которую нашёл первой только один запрос.
- Температура 0 не делает DeepSeek детерминированным ни в плане, ни в ответе.

## Вывод

Общая причина — недетерминированность модели (план поиска и выбор цитируемых страниц), а не поиск: поиск по
одним и тем же запросам детерминирован. «Те же страницы 3 из 3» температурой и слиянием выдачи не достигается.
Итог (засчитан / нет) у `main` уже стабилен у 19 из 20 вопросов; колеблется Q16.

Оставлено: план поиска с температурой 0 (вреда в замерах нет), настройка `LLM_TEMPERATURE` (по умолчанию 0,2,
как было), `make eval-stability`. Слияние выдачи и «сам вопрос первым» — не взяты: счёт хуже или не лучше.
