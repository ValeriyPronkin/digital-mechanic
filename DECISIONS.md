## D-11 · Стенд: разговор у клиента под подписью, лимит частоты на чат · 26.11, день 1

- **Контекст:** стенд — Serverless Containers: запросы одного механика могут попасть в разные экземпляры, после
  простоя экземпляр пересоздаётся; разговор в памяти процесса терялся бы («Отправить» → «разговор не найден»).
- **Решение:** состояние разговора (сообщения, найденные фрагменты, черновик) — сжатая строка с HMAC-SHA256
  (`APP_SECRET`; на стенде — производный от секрета сервисного аккаунта, общий для всех экземпляров); клиент её
  только возвращает. Повторная отправка того же черновика отсекается по отпечатку (в пределах экземпляра).
  Лимит частоты на `/api/chat` и `/api/tickets`: 10 в минуту на IP (последний адрес X-Forwarded-For) и 60 в минуту
  на экземпляр (`CHAT_RATE_PER_MIN`, `CHAT_RATE_TOTAL_PER_MIN`). Заглушки — отдельные контейнеры `stand-…-ml`,
  `stand-…-toir` из `docker/mock.Dockerfile`, их адреса workflow кладёт в окружение основного.
- **Почему:** липких сессий у Serverless Containers нет; общее хранилище для разговоров — лишняя инфраструктура.
- **Кто:** агент. **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `test_chat_and_ticket_survive_instance_switch`, `test_tampered_state_rejected`, `test_chat_rate_limited`; смоук в `stand.yml`.

## D-9 · Где хранить PDF и индекс для стенда · 26.11, час ~4 · решено 26.11 (issue #6)

- **Контекст:** PDF (6 шт., до 99 МБ) и индекс в git и в образ не кладём (issue #3, п. 8). Стенду индекс нужен при старте.
- **Предложение агента:** частный бакет Yandex Object Storage: `manuals/` — PDF, `index/<версия>/` — собранный `.index/` без `cache/extract` (~десятки МБ: fragments.jsonl, vectors.npy, passport.json, кэш эмбеддингов). Индекс собирается локально `make index`, выкладывается одной командой; контейнер при старте скачивает `index/<версия>/` в `INDEX_DIR` (ключ сервисного аккаунта только на чтение — секретом стенда).
- **Варианты:** (а) Object Storage, рекомендация; (б) отдельный том/диск стенда — Serverless Containers его не дают; (в) собирать индекс при старте контейнера — минуты и платный OCR/эмбеддинги на каждый холодный старт.
- **Решение (Валерий, штурман, issue #6):** вариант (а). Бакет `digital-mechanic-kb` (переменная `S3_BUCKET`), `index/<версия>/` + `index/LATEST`. Выкладка — локально по статическому ключу (`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY` в `.env`). Стенд читает по IAM-токену своего сервисного аккаунта из метаданных; статический ключ в контейнер не кладём.
- **Реализация (агент):** `service.kb_store`; версия — `ГГГГММДД-ччммсс-<sha8 fragments>`, `MANIFEST.json` с sha256 и размером, стенд пишет только файлы из белого списка и заменяет каталог после сверки. В бакет не идёт `cache/extract` (кэш извлечения), идёт `cache/embeddings.jsonl` (кэш эмбеддингов запросов). PDF стенд не качает (до 99 МБ на экземпляр в памяти): ссылка на страницу — номер и цитата, без открытия PDF. Ошибка скачивания не роняет стенд: поиск пуст, смоук workflow краснеет при заданном `S3_BUCKET`.
- **Кто:** агент предлагает, решает человек (issue #6).
- **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `tests/test_kb_store.py` (подпись SigV4 по эталону AWS, чтение только по IAM, порча файла, чужие имена); смоук стенда — `/health` → `manuals_index.present` после холодного старта.

## D-8 · Индекс руководств: извлечение и поиск · 26.11, час ~4

- **Контекст:** issue #3 — ответы только по руководству двигателя ТС со ссылкой на страницу PDF.
- **Решение:** текст — pypdfium2, таблицы — pdfplumber (PyMuPDF — AGPL, не берём). Номер страницы — только номер PDF с 1; печатный номер и смещение — в паспорте (РЭ ЯМЗ-536: печатный = PDF − 1). Разделы — из страниц оглавления (заданы в `catalog.py`), в РК ЯМЗ-536 оглавления нет — раздел из заголовка модуля данных. Таблицы неисправностей pdfplumber сам не собирает: колонки по вертикальным линиям строки, строки по горизонтальным; разбор с порванными словами отбраковывается, страница остаётся текстом. Поиск: фильтр по двигателю до ранжирования + повторная проверка после; BM25 по леммам (pymorphy3) и эмбеддинги Yandex (doc/query) параллельно, слияние RRF (k=60). Без ключа Yandex — только BM25. Неизвестный двигатель — ошибка, а не поиск по всем.
- **Почему:** лицензии (только MIT/BSD/Apache); фильтр до поиска делает чужую ссылку невозможной по построению. Отброшено: один общий векторный поиск с фильтром после (чужие документы вытесняют свои из топа), разбор таблиц через `extract_tables` (склеивает колонки).
- **Данные во внешний сервис:** в Yandex (OCR, эмбеддинги) уходят только страницы руководств — так поставлено в issue #3; данные ТС и ответы ML не уходят.
- **Кто:** агент.
- **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `scripts/verify_index.py` (20 страниц против PDF, 10 запросов × 4 двигателя, 0 чужих), `tests/test_manuals*.py`.

## D-5 · Заявка уходит только по отпечатку показанного черновика · 26.11, день 1

- **Контекст:** issue #5, п. 4 (суть D-19 штаба): механик подтверждает ровно тот состав, что видел.
- **Решение:** черновик собирает код (машина, проверка, код из ML, срочность, ссылки только из найденных в разговоре
  страниц); отпечаток — sha256 канонического JSON. `POST /api/tickets` шлёт в ТОиР, только если отпечаток совпал
  с последним черновиком и правила (статус, совместимость, работы, ссылки) проходят повторно; после отправки
  черновик гасится. Цифры в работах и заключении сверяются с фрагментами, как и в ответе.
- **Почему:** модель может переписать черновик после показа; отпечаток делает это видимым.

- **Что проверит:** `test_fingerprint_mismatch`, `test_no_ticket_*`.

## D-1 · Карточка вердикта — чистый код, description только цитатой · 26.11, день 1

- **Контекст:** issue #2; правила 1, 2, 7 из CLAUDE.md должна охранять программа, а не модель.
- **Решение:** `verdict_policy.build_card` решает только по `status`, `anomaly_type`, `anomaly_score`, `confidence`,
  `signal_quality`; `description` попадает в карточку полем `ml_quote` и выводится на странице через `textContent`.

  «Норма, но повторить раньше срока» — жёлтая карточка. В истории ТС статус проверок не показываем до нажатия кнопки.
- **Почему:** инъекции в `description` (S-0043, S-0113, S-0195) не должны ничего менять; тест подменяет `description`
  во всех 195 карточках и сравнивает остальные поля.
