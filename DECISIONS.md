## D-6 · Срочность заявки и совместимость — правила в коде · 26.11, день 1

- **Контекст:** issue #5, п. 4; правило 5 (I-01).
- **Решение:** `urgency_for`: F02, F03, F14 или `anomaly_score ≥ 0,85` → high; `confidence < 0,6` или `warning` → low;
  иначе medium; основание показывается механику. Совместимость — `data/compat.json` по признакам двигателя (топливо,

  отклонений из 69 — все без заявки.
- **Почему:** срочность и допуск заявки не должны зависеть от модели и от `description`.
- **Кто:** агент. **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `test_incompatible_code_blocks_ticket`, `test_c1_anomaly_to_ticket`; полную таблицу — матрица по руководствам (#3).

## D-5 · Заявка уходит только по отпечатку показанного черновика · 26.11, день 1

- **Контекст:** issue #5, п. 4 (суть D-19 штаба): механик подтверждает ровно тот состав, что видел.
- **Решение:** черновик собирает код (машина, проверка, код из ML, срочность, ссылки только из найденных в разговоре
  страниц); отпечаток — sha256 канонического JSON. `POST /api/tickets` шлёт в ТОиР, только если отпечаток совпал
  с последним черновиком и правила (статус, совместимость, работы, ссылки) проходят повторно; после отправки
  черновик гасится. Цифры в работах и заключении сверяются с фрагментами, как и в ответе.
- **Почему:** модель может переписать черновик после показа; отпечаток делает это видимым.
- **Кто:** агент. **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `test_fingerprint_mismatch`, `test_no_ticket_*`.

## D-4 · Агент: модель выбирает инструменты, контекст и проверки — у кода · 26.11, день 1

- **Контекст:** issue #5; правила 2–4 и жёсткие ограничения (ПДн, лимит расходов).
- **Решение:** провайдеры DeepSeek и GigaChat на `httpx` (без SDK, новых зависимостей нет). Разговор привязан к машине
  и проверке: аргументы модели про другую машину отклоняются, двигатель для поиска берётся из карточки ТС.
  `description` идёт модели в обёртке `<<<ДАННЫЕ…>>>` (маркеры внутри текста вырезаются). Ответ проходит `guard`:
  ссылки [Rn] — только на найденные фрагменты; предложение с цифрой не из процитированных фрагментов и не из карточки
  удаляется с плашкой; без ссылки — плашка «без ссылки на руководство»; утечка системного промпта заменяется отказом.
  ПДн маскируются до модели; лимит ₽ проверяется по журналу до каждого вызова. Журнал и память по ТС — SQLite.
  Поиск — прослойка над `ManualIndex` из #3, пока его нет — пустой поиск (`STUB: search-until-#3`).
- **Почему:** модель ошибается и поддаётся инъекциям; всё, что охраняют правила, решает код.
- **Кто:** агент. **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `tests/test_agent.py`, ручной прогон `reports/2026-11-26-s2-live.md`.

## D-1 · Карточка вердикта — чистый код, description только цитатой · 26.11, день 1

- **Контекст:** issue #2; правила 1, 2, 7 из CLAUDE.md должна охранять программа, а не модель.
- **Решение:** `verdict_policy.build_card` решает только по `status`, `anomaly_type`, `anomaly_score`, `confidence`,
  `signal_quality`; `description` попадает в карточку полем `ml_quote` и выводится на странице через `textContent`.
  Название неисправности берётся из `fault_types.json` по коду, а не из `anomaly_title` ответа. `signal_quality = bad`
  при любом статусе — как `check_failed` (без выводов). Код вне справочника — заявка невозможна.
  «Норма, но повторить раньше срока» — жёлтая карточка. В истории ТС статус проверок не показываем до нажатия кнопки.
- **Почему:** инъекции в `description` (S-0043, S-0113, S-0195) не должны ничего менять; тест подменяет `description`
  во всех 195 карточках и сравнивает остальные поля.
- **Кто:** агент.
- **Нарушает совет из PLAYBOOK:** нет.
- **Что проверит:** `tests/test_verdict.py`.
